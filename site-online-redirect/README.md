# orgculture.online → orgculture.ru

Резервный домен просто переадресуется на основной. Содержимое этой папки
нужно залить в корень хостинга, который обслуживает **orgculture.online**
(не orgculture.ru — это отдельный, основной сайт из папки `site/`).

## Как настроить редирект — три варианта, нужен только один

**1. Netlify** — просто положи `_redirects` в корень. Готово, ничего
больше настраивать не нужно, Netlify подхватит файл автоматически.

**2. Vercel** — `vercel.json` уже настроен на 301-редирект с сохранением
пути (`/texts/medeya/` → `orgculture.ru/texts/medeya/`).

**3. Обычный хостинг с Apache** — `.htaccess` делает то же самое через
mod_rewrite. Подходит для reg.ru/timeweb/beget и большинства
классических хостингов.

**4. Если ничего из перечисленного не поддерживается** (статичная
раздача файлов без сервера/rewrite) — `index.html` сработает как
универсальный fallback: редиректит через `<meta refresh>` и JS,
подставляя текущий путь. Но сработает он только на тех адресах, для
которых хостинг реально отдаёт этот файл — обычно это только корень
(`orgculture.online/`), если явно не настроен catch-all на index.html
для любых путей.

## Что лучше сделать на самом деле

Проще и надёжнее всего — вообще не хостить отдельный сайт на
orgculture.online, а настроить переадресацию доменов прямо у
регистратора (там, где покупали домен — обычно это делается в панели
управления DNS/доменом, пункт вроде «переадресация домена» или
«URL forwarding», без необходимости отдельного хостинга под этот
домен). Тогда файлы из этой папки вообще не понадобятся.
